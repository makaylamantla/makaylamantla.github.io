## GOLDEN RULE — Sequential Python Method and Function Naming

Canonical name: `_tk_NNNN_actionTargetNNN` (example: `_tk_1234_getVariable001`). `NNNN` is a unique, repository-wide, sequential, permanent method/function identifier starting at `0001`; never renumber or reuse retired IDs. The final `NNN` is a three-digit target/operation identifier (independent of the method ID). Use an approved normalized lowerCamelCase action and PascalCase target, such as `getVariable001`, `setVariable001`, `listFiles001`, `readFile001`, `writeFile001`, `createFolder001`, `updateRecord001`, `deleteFile001`, `validatePath001`, `checkStatus001`, `syncDrive001`, `mergePdf001`, `convertImage001`, `calculateHash001`, `generateReport001`, `loadConfig001`, `saveConfig001`, `runWorkflow001`, `startServer001`, `stopServer001`, `publishPdf001`, `auditDrive001`, or `verifyOutput001`. Preserve Python special methods (`__init__`, `__call__`, etc.) and existing public APIs, CLI contracts, FastAPI routes, callbacks, imports, and external integrations through compatibility aliases/wrappers where needed. Record each ID, canonical name, original name, class, purpose, and revision in a README registry. Assign new IDs only when adding new methods/functions. Renaming existing code requires updating all references and passing tests before deployment. This section documents the policy; it does not imply existing source has been refactored.
